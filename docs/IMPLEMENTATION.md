## Reproduce the gates

On this branch, Node and Bun each passed 24 tests, including a two-process workspace claim test and real stdio client tests for both MCP protocol revisions. Three real Docker cases were skipped locally because Docker Desktop could not start. The shared extension success and failed-probe paths also passed with a test substitute for the Docker CLI. Linux CI runs them against a real container. Both Swift fixture tests, the live Swift-to-Node integration test, the iOS Simulator SDK type check and the React production build passed. Browser checks exercised Diff confirmation, the failed release path, and the change from stacked panels to separate pages at 390 px, including persistence on reload. The contextual suggestion was also dismissed, applied and reverted in the browser.

- `pnpm test` and `pnpm test:bun` exercise the workbench, a deterministic provider fixture, invalid preview rejection, existing snapshots, and signed catalog checks. The live Docker case requires `IDAS_SANDBOX_IMAGE` and runs in Linux CI.
- `pnpm --filter idas-web check && pnpm --filter idas-web build` checks the interactive host. Use `pnpm web` and the four example intent buttons to exercise the browser flow.
- `swift test --package-path packages/sdk-swift` validates both the legacy fixture and the shared workbench projection. CI also type-checks the renderer against the iOS Simulator SDK.
- `pnpm schema` regenerates the IDSS JSON Schema from the same contracts used by the runtime.

The current workbench tests use a deterministic local compiler or a fixture model provider. They establish runtime behavior and integration boundaries. The HTTP model adapter has a fixture transport test. Real-model instruction coverage remains a separate gate in the roadmap.
